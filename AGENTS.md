## Источники и оформление

- Проекты: `content/projects/*.yaml`; порядок и три работы главной: `content/site.yaml`; генератор: `build-projects.py --html-only`.
- Статьи: `content/guides/*.md`; услуги: `build-services.py`, `site_common.py`, `site_i18n.py`; SEO: `seo.py` и `build-seo.py`.
- Интерфейс и переводы: `app.js`, `styles.css`. Дизайн спокойный, тёплый; сохранять существующее оформление.
- Соблюдать `.cursor/rules/copy-typography.mdc`: в новых пользовательских текстах короткое тире `-`, заголовки вкладок `.eyebrow`, ссылки возврата по существующим образцам. Наличие старых длинных тире не повод массово переписывать тексты.
- Не выдумывать цены, услуги, историю заказчиков или детали интерьеров. Статьи с незакрытыми вопросами и местами для фото не публиковать. Новые статьи готовить пачками по три с показом Эмину.
- Секреты из `deploy.env*`, `api/brief-secrets.php`, `oauth/oauth-secrets.php` не выводить и не включать в коммиты или документы.

## Сборка и публикация

- `bash prepare-deploy.sh` меняет сгенерированные HTML, изображения hero, версии ресурсов и пересоздаёт `dist/`. Это не read-only проверка.
- `bash serve.sh` собирает сайт и запускает просмотр с чистыми адресами; скрипт может остановить процесс, занявший выбранный порт. Перед запуском проверить порт.
- Firebase - основной сайт по последним записям. GitHub Actions при push в `site-clean` публикует зеркало Timeweb, не Firebase.
- Не использовать `_hotfix` как рабочую копию без проверки: её Git-ссылки сохранили абсолютные пути другого окружения `/sessions/...`.
